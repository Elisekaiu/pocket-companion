# 08 · 踩过的坑

做这个过程中出过的问题，大致按发生的顺序排列。

## 角色和美术

- **生成角色穿每一套衣服的图。** 每张图都会把身体结构重画得不太一样，任何锚点系统都修不了会动的身体结构。→ 每个姿势家族一个基础图 + 只含衣服的图层（见 04）。
- **耳机不管怎么缩放都挡住眼睛。** 一张图同时对不准两只耳朵和头梁。→ 把物品拆成部件。
- **衣服“太小”。** 覆盖率把翅膀和尾巴也算进去了。→ 在躯干上量。
- **衣服看起来空空的。** 太长了，只有领子落在身上。→ 重新裁源图的矩形，不要放大。
- **视觉上偏了。** 数学上居中、但细节不对称的衣服，看起来就是偏的。→ 每套衣服做一点 x 微调，靠眼睛判断。
- **长大了却看不出变化。** 只改了一个数字的成长阶段，感觉什么都没发生。→ 让成长体现在精灵图上：会变的标记、小星星闪烁、光环。

## 素材和渲染

- **从合成截图里抠按钮。** 边缘更软、像素密度不同、底部缺了一块。→ 用专门的高清素材图，带边距裁剪，统一规格（见 06）。
- **抠背景把浅色边缘吃掉了。** 反复去背景会毁掉抗锯齿的轮廓。→ 只抠一次，从 alpha 通道小心地抠。
- **某个主题下出现黑框或白框。** 素材自带了背景。→ 全部透明，两种主题都测。
- **手机上的文字又糊又重叠。** 小尺寸的像素网页字体。→ 字形图集 + 整数倍缩放。
- **日间模式的字“太浅”。** 灰色是在显示器上调的。→ 一直加深，直到在户外的手机上也看得清。
- **某一个状态格比别的小。** 文字长一点就把布局撑变了。→ 等高、可伸展的格子。

## 后端

- **重抽。** 在读取时用 `Math.random()` 来选，一刷新，小宠物说的话就变了。→ 用固定哈希，并把决定存在事件上。
- **把 AI 当成了人。** 如果 AI 的操作会让人“出现”，小宠物就永远不会想念任何人。→ 每个事件标上是谁、在哪里；陪伴只来自人。
- **假装很忙。** 因为是晚上就显示“在读书”，这是在说谎。→ 只显示有证据支持的状态，并说明证据是什么。
- **会写入的沙盒。** 在真宠物身上测试，会留下假的历史。→ `simulate` 在内存里用虚拟时钟跑真正的操作；有测试断言真实记录没有变化。
- **用自动化浏览器打开真正的房间。** 页面会发出“我在”的信号，结果小宠物以为人凌晨三点来过。→ 对生产环境做自动检查时，拦截所有非 GET 请求。

## 文字

- **人称混乱。** 同一个列表里有的句子用“他”，有的用“我”。→ 统一用一种人称写，按场景转换。
- **漏出来的标签。** 中文句子里出现英文标签。→ 每个标签都要有名字；用抽样来测。
- **子字符串陷阱。** `考试过了` 里的 `考试`；`难过了` 里的 `过了`。→ 长短语优先；选触发词时避开“相反短语的一部分”。
- **通用内容淹没了当地内容。** 14 句里只有 2 句当地的，几乎永远轮不到。→ 按来源加权。

## 部署

- **单文件挂载跟随 inode。** 用 `mv` 或 `install` 替换文件会产生新的 inode，挂载这个单文件的容器会继续提供旧文件。→ 原地复制（`cp`），并确认 inode 没变。
- **别人改过生产环境。** → 每次部署前，把生产环境和你上次部署的版本对比；合并，绝不覆盖。
- **每一次都要**：备份被替换的文件，在备份旁边写好回滚说明，核对线上文件的哈希，做只读的冒烟测试。
